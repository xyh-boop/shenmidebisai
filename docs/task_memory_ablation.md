# Task-memory 双框架合并消融实验

> 本节是本次修订后的正式结果。文档后面的旧版单框架结果保留作历史记录，不作为本次结论。

## 两种设计

- **框架 A：生命周期状态机**：管理任务处于 active、completed、superseded 哪个阶段，以及哪些状态切换是非法的。
- **框架 B：追加式证据账本 + 检索**：每条结论只追加不覆盖，查询时按任务和关键词找有证据的当前结论，修正通过 supersedes 链保留历史。

实际脚本结果（每组 9 个场景）：

| 框架 | 完整版 | 去掉核心能力后的结果 |
| --- | ---: | --- |
| A 生命周期状态机 | 9/9 | 去 preflight 8/9；去 finalize 5/9；去 supersede 6/9；去边界保护 5/9 |
| B 证据账本 + 检索 | 9/9 | 去 retrieve 5/9；去 evidence 8/9；去 supersede 7/9；去边界保护 7/9 |

## 第二部分：《双框架消融实验诊断报告》

### 1. 功能完整性与退化分析

框架 A 证明“任务状态是否合法”；框架 B 证明“历史事实是否有证据、是否仍然有效”。两者不是同一个能力的不同写法：A 擅长阶段门禁，B 擅长跨任务检索和证据追溯。实验脚本现在会分别输出 `lifecycle_state_machine` 与 `evidence_ledger_retrieval` 两组结果。

### 2. 指令冲突与负向迁移评估

共同场景要求两框架都处理“已完成后再替代”和“新旧结论同时活动”。A 应拒绝非法状态迁移；B 应返回 conflict 而不是自行选一条。只关闭单个能力时，失败应落在对应场景，不能用 A 的状态分数代替 B 的检索分数。

### 3. 性能与资源消耗统计

当前仍是标准库确定性实验，没有模型调用，所以 Token、真实端到端 latency、模型 context window 均为**未测量**。脚本可继续记录固定语料上的 wall-clock、存储字节数、返回字符数；接入模型后再报告 tokenizer 统计和 P50/P95。

### 4. 鲁棒性与边界抗压能力

新增的共同压力包括无证据声明、无关查询、空查询、未知任务、冲突声明和跨任务精确检索。重点检查：读操作是否误写、旧结论是否被错误返回、泛词是否造成大量误命中。并发、超长文本和持久化故障仍未测量。

### 5. 结论与下一步优化 Action

结论暂定为**两框架互补，不能只保留其中一个**：A 负责“现在能不能做”，B 负责“过去什么结论可信”。如果产品只需要简单任务收尾，A 更轻；如果需要跨轮交接、证据引用和修正历史，B 更合适。下一步应运行双框架脚本，保存每个场景的原始结果，再补真实模型 Token、P50/P95 latency、context 和人工标注的检索准确率。

实验对象是 `tasks/ablation_task_memory.py` 所建模的 task-memory 生命周期语义：
`preflight`、`finalize`、`supersede` 与状态边界保护。实验产物为
`artifacts/task_memory_ablation_results.json`。以下 Prompt 是可复现的功能验收
输入；实际得分来自该脚本的 9 个确定性状态机场景，并非模型自我评分。

## 第二部分：《消融实验诊断报告》

### 1. 功能完整性与退化分析

完整实现通过 9/9（100.0%）场景，说明在本实验模型中四项组合语义均被保留。单项移除的通过率为：去除 preflight 8/9（88.9%，-11.1 个百分点）、去除 finalize 5/9（55.6%，-44.4 个百分点）、去除 supersede 6/9（66.7%，-33.3 个百分点）、去除边界保护 5/9（55.6%，-44.4 个百分点）。

退化可定位为：preflight 缺失导致重复预检不再复用；finalize 缺失导致完成及相关状态约束无法成立；supersede 缺失导致变更任务无可追溯替代链路；边界保护缺失使非法转换和空标识进入状态机。该实验未生成自然语言输出，**未测量信息遗漏、幻觉或错误率**，不能据此声称它们没有上升。

### 2. 指令冲突与负向迁移评估

冲突状态转换已被确定性覆盖：完整实现拒绝“已完成后再替代”和“已替代后再完成”，同时保留旧任务到替代任务的单向链路。移除 finalize 或边界保护时，前一冲突场景失败；移除 supersede 或 finalize 时，旧任务保护相关场景失败。这是合并后逻辑互斥的直接证据。

不过，脚本不调用大语言模型，未执行多段自然语言 Prompt、超长文本或优先级相抵触的指令跟随测试。因此，**指令遗忘、Skill 抢戏和负向迁移在模型提示词层面未测量**；当前结论仅限状态转换冲突。

### 3. 性能与资源消耗统计

本实验使用标准库内存状态机，不调用网络或模型。JSON 仅包含确定性功能结果。**Token 消耗、端到端模型 latency、上下文窗口（Context Window）占用均未测量**，也没有合并前的同环境基线，故不能计算成本降低比例或响应时延差异。脚本本身的运行时间不是模型端到端 latency，不应替代该指标。

后续性能实验应在固定模型、固定输入、固定并发和重复次数下，记录每个原始 Skill 与合并 Skill 的输入/输出 token、P50/P95 延迟、最大上下文长度和失败率，并报告均值与样本数。

### 4. 鲁棒性与边界抗压能力

两类边界输入已覆盖：未知任务完成与空标识预检；两类状态压力已覆盖：完成后替代、替代后完成。完整实现均通过，且输出状态为稳定的 `unknown_task`、`invalid_task_id`、`superseded_task` 或拒绝结果。移除边界保护后仅 5/9，表明输入校验和状态门禁对于输出可控性不可缺少。

该压力范围不包含并发写入、持久化失败恢复、超长文本、特殊符号编码或大规模任务集。因此，对这些压力条件的鲁棒性仍为**未测量**，不应从 9/9 外推。

### 5. 结论与下一步优化Action

定性结论：**部分成功**。完整变体已在所建模的九项生命周期语义上达到 9/9，且消融定位了 finalize、边界保护和 supersede 的必要性；但模型层指令冲突、token、端到端 latency、上下文占用及真实检索质量均未测量，尚不足以宣称整体合并完全成功。

下一步 Action：

1. 在 Prompt 中固定任务标识、期望状态和允许迁移，例如“仅对 `active` 任务执行 supersede；完成已替代任务必须返回拒绝原因码”。
2. 为 retrieve/evidence 明确数据契约，并新增独立测试：检索目标、命中判定、证据字段、缺失证据的拒绝策略和稳定排序。
3. 以原始独立 Skill 为对照运行真实模型评测，采集 token、P50/P95 latency、context 与输出正确率；所有未测量字段在报告中保持“未测量”。
4. 当自然语言输入需要同时决定 preflight、finalize 与 supersede 且规则无法通过显式状态参数消解时，再评估引入前置 Router；当前确定性状态机场景不需要 Router。
